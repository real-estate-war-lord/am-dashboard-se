# P3 — Sweden fit: levels, vocabulary, defaults, search

Sweden's strength is DeSO/RegSO data; rents, prices, K/T-tal, construction and crime exist only per kommun.
The UI must be honest about that and lead with what exists below kommun.
1. **Headline tiles**: five figures published at DeSO/RegSO where possible — population growth, median income,
   hyresrätt share, post-secondary education, employment rate — plus at most one kommun-only figure (rent
   SEK/m²/yr) explicitly labelled "municipality figure". Same set on the map card, area page and Test property.
   Log the final choice in DECISIONS.md.
2. **Kommun-only indicator while drilled into RegSO/DeSO**: never paint every sub-area one flat colour as if it
   were local data. Draw the kommun outline filled with the kommun value and the sub-areas as neutral outlines,
   with the note "published per kommun only" in the info strip and legend. Check: `#map/0180?ind=rent&lvl=regso`
   has no RegSO paths with the choropleth fill.
3. **Tenure vocabulary**: hyresrätt / bostadsrätt / äganderätt (English gloss once, in the picker's help),
   allmännytta where relevant; K/T-tal is never called a price per m².
4. **Charts default**: opens with Stockholm, Göteborg, Malmö, Uppsala and the Sweden median instead of
   "Nothing to plot yet" (an explicit empty set still possible via the URL).
5. **Search**: diacritic-insensitive (goteborg, malmo, sodermalm → Södermalm RegSO), aliases (Stockholms stad,
   Gbg, Sthlm), RegSO names searchable. Pure matching logic in a `src/search_core.js` IIFE with node tests.
6. **Units on tiles**: rent tiles show "SEK/m²/yr"; the ±margin of error is explained on hover ("±28 = SCB
   margin of error") instead of a bare grey "±28".
